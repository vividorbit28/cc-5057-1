# 轨道站拼装台 · 关卡模块生成器

用自制走廊、设备舱与连接件，按**接口类型 / 朝向 / 边界尺寸**拼装可实际进入的三维轨道站场景。
求解器带可复现种子与失败解释；界面可逐步观察选择与回退，并保存生成清单。

## 图形入口（主）

```bash
node ui/server.js          # 默认 8080 端口
# 打开浏览器访问 http://localhost:8080/ui/
```

零依赖、纯 ES 模块，无需 npm install、无需构建。**关卡编辑视窗是主入口**：
模块托盘（按套件分组，含接口/通行高度提示）、拖放拼装、生成与逐步回放、
套件校验结论、验收报告与可行连接列表都在界面内完成。

## 命令行（仅辅助）

命令行只用于批量生成清单、重建核验与策略对比，不承担拼装交互：

```bash
node kernel/cli.js --preset deck --seed demo-2    # 生成并输出清单到 out/
node kernel/cli.js --preset list                  # 列出预设
node kernel/rebuild.js --all out                  # 重建核验全部清单（旧样例兼容）
node kernel/compare.js                            # 正向生成 vs 逆推缺件 策略对比
node --test 'tests/*.test.js'                     # 全部测试（48 个）
```

## 玩法（界面）

- **生成关卡**：选预设与种子 →「生成关卡」→ 用 ⏮ ◀ ▶ ⏭ / 自动播放逐步观察求解器的
  放置、局部改向、全局回退、闭环提交/放弃与封死回溯（nav-sealed）决策。
- **手动拼装**：从模块托盘拖入视窗，Q/E 旋转；内核实时判定，非法放置会被拒绝并说明理由
  （重叠 / 门洞被墙堵死 / 接口类型或朝向不匹配 / 间距不足 / 越界）。
- **结果区**：点击开放端（绿色门框）→ 列出内核按实际几何计算的**可行连接**，点击直接落位。
- **套件校验**：右栏列出各套件的校验结论——故意不兼容部件声明、可互换接头的
  通行高度差异（何时必须回溯）、舱内连通实测。
- **验收**：对当前装配件做几何碰撞 + 导航通路检查，乘客路线以红线画在场景中；
  连通阻断时点名阻断件（部件身份 + 障碍标签 + 格数）。
- **保存生成清单**：导出清单 v2（种子、规格、套件来源与参数、部件身份哈希、
  可拼装接口资料、放置、连接、开放端、演示路线、验收报告）。

## 模块套件（`kits/`）

套件是**可拼装的接口资料**，不是美术网格：每个模块带尺寸、接口（类型/朝向/位置/宽高）、
舱内障碍、实测通行高度与部件身份哈希。套件文件保存**来源与参数**
（`source.origin`、`params.passengerClearance` 等），加载时随模块注册。

内置 `deck-kit`（双层站台套件）演示全部套件能力：

| 模块 | 说明 |
|---|---|
| `deck-hall` | 8×6.4×8 双层大厅，4×C2，楼梯 + 夹层板 |
| `deck-corner` | 转角舱，N+E 双 C2，结构柱 |
| `deck-link-low` / `deck-link-high` | **可互换接头**：尺寸与接口完全相同（3×3×3，2×C2），实测通行高度 1.1m vs 3.0m——接口约束无法区分 |
| `deck-service` | **故意不兼容部件**：D1 检修接口（1.2×2.0），全注册表无配合件，已声明原因 |
| `deck-cargo` | 10×6.4×10 货舱，C4 货运接口 |

套件校验（`validateKit`）在加载时执行并解释**何时必须回溯**：

- 接口配对矩阵：端口 < 2 的接口类型 = 死件，必须声明 `incompatible.reason`，否则报错；
- 舱内连通实测：乘客净高 2.0m 下门洞↔导航点必须互达（低矮件声明 `low-clearance` 后降级为提示）；
- 通行高度变体对：同尺寸同接口分组内实测通行高度不同 → 警告"接口约束无法区分，
  乘客路线被迫穿越时必须回溯更换变体"。

## 策略对比：正向生成 vs 逆推缺件

`node kernel/compare.js` 实测（种子 cmp-1，结果存 `out/strategy-comparison.json`）：

| 策略 | small | medium | deck | 适用情形 |
|---|---|---|---|---|
| 正向生成（按连接口约束） | 51 节点 / 13ms | 17 节点 / 7ms | 16 节点 / 9ms | 只有库存与目标，全量搜索 |
| 逆推缺件（从成品清单核销库存） | <1ms | <1ms | 1ms | 有成品清单；篡改库存即报 `{"corr-straight":1}` |
| 补缺完成（拆 3 件再补回） | 6 步 / 4ms | 5 步 / 3ms | 4 步 / 2ms | 缺什么已知 |

异高接头的决定性证据（deck 场景）：被迫几何下 `deck-link-low` **接口约束全过、
几何完成**，但验收导航断裂，阻断证据指向 `deck-link-low(m733)`（过街主管道，净高1.1m，
4 格）——必须回溯更换高通行变体；同几何换 `deck-link-high` 后验收通过。
正向自由放置则直接绕开低矮件成功。

## 内核约束（`kernel/`）

| 约束 | 实现 |
|---|---|
| 接口匹配 | 类型一致（C2/C4/D1）+ 朝向相对 + 门洞边界重合；不匹配即拒绝，不做视觉遮挡 |
| 不重叠 | 模块包围盒严格相交检测（贴面合法） |
| 门洞不被堵 | 门洞外探盒碰到邻模块时，邻模块必须有对齐接口，否则拒绝 |
| 区域间距 | 指定标签舱室的 AABB 最小间距（如 反应堆↔医疗舱 ≥ 8m） |
| 入口→目标舱连通 | 装配几何上 0.5m 导航网格 BFS（乘客净高 2.0m），绕过舱内设备障碍 |
| 闭环提交 | 最后一接口落位成环时，以乘客可达路线 + 出口账面决定是否提交 |
| 封死回溯 | 开放端耗尽且仍有剩余模块 → 立即回溯；目标舱导航区域无开放端 → 连通不可恢复，立即回溯 |
| 可复现 | 同一种子 → 同一份清单（字节级一致）；求解器随机开放端选择由种子驱动 |
| 失败解释 | 返回冲突模块与条件（含"接口类型互不匹配"点名）；搜索有节点预算，不无限重试 |

## 验收与重建核验

`validateScene` 从**实际装配结果**重建碰撞体（墙体在门洞处真实开洞）与可通行表面，
做几何碰撞、接口审计、间距复验与导航通路检查；篡改场景（移动模块）必然验收失败。

`kernel/rebuild.js` 对清单做入库级核验：清单格式、模块资产真实存在、
部件身份哈希一致（v2）、模块源文件记录、逐步重建通过内核检查、连接关系一致、
重建装配通过验收、验收统计与乘客路线数量符合约定。v1 旧样例按当前注册表兼容核验。

## 目录

```
kernel/    拼装内核：geom / modules / assembly / solver / validate / kit / kitio /
           reverse / rebuild / compare / exhaustive / generator / cli（仅辅助）
kits/      内置套件：deck-kit（双层站台·异高接头·故意不兼容件）+ 套件索引
ui/        关卡编辑视窗（图形入口）：viewport(软件3D) / editor(拖放) / main(生成与回放) / server
tests/     node --test 测试：几何、模块、求解、套件、双层站台、逆推、重建、穷举核对、验收、界面冒烟
out/       示例生成清单（含 v2 双层站台清单）与策略对比结果
```
